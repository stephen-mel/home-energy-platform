# Trusted confirmed-SMART receipt issuance

`issueConfirmedSmartReceipt(capability, initialRecord, classifiedRecord)` accepts only the existing runtime capability and exact B1 records. Its first authority check is `journalCompletionForRecords`. Invalid authority, mismatched records or malformed B1 evidence return `JOURNAL_COMPLETION_NOT_BOUND`; the issuer deliberately does not broaden B2 to distinguish those cases.

Only the canonical `submitted-representation-preserved` outcome qualifies. B2 verification reuses B1's underlying API/comparison/classification checks. The normalized accepted API outcome originates from `interpretWriteResponse`; HTTP 2xx without recognised acceptance remains unknown. Raw HTTP bodies are neither retained nor independently reconstructed by the issuer. The existing trusted executor/transport boundary remains necessary: journal completion is not independent proof of Tesla-origin authenticity against hostile privileged code.

The issuer and pure finaliser share `validateConfirmedSmartReceipt`. This preserves the existing confirmation binding, numeric HTTP-success, approval/capture/readback timing, prior-generation and exact authenticated complete-timeline checks. Validation performs no ownership derivation. The finaliser alone subsequently checks economics, coverage and restoration lineage and derives a transition. Issuance is not a promise that finalisation or persistence will succeed.

Every receipt field is projected from authorised records: the original review's proposal/payload, exception approval, frozen preparation ownership capture/generation/evidence, classified attempt/completion/API/readback/classification, and B2's stable classified completion time. Missing ownership maps to null generation/evidence; valid-empty ownership retains its generation and empty evidence. No time, override, fresh observation or replacement proposal is accepted.

Receipt projection keys retain their existing meaning: `originalKey = hash({ mutationId, original })` and `classifiedKey = hash({ mutationId, execution })`. They are not B1 record IDs. `receiptKey = hash(receipt)` remains the finaliser's identity. The detached, deeply frozen issued envelope adds B2 completion evidence and `issuanceKey = hash({ version: 1, completion, receiptKey })`. Different exact journal chains can project the same receipt but have different issuance keys. No timestamp or random identity is generated.

The receipt/envelope are evidence, not a second runtime capability or standalone persistence authority. Repeated issuance is deterministic and does not consume B2 authority or perform I/O. Future production persistence must originate from/revalidate the genuine B2-authorised path, not accept arbitrary receipts or pure finaliser results. Serialization and restart do not restore B2 authority. There is no recovery reader or receipt persistence contract.

The selected original SMART interval remains the only authorised import scope. Full representation/readback checks preserve observed export state; unexpected export transformations do not qualify. Finalisation never creates export ownership. Domain containment remains separate from actual economic coverage; later finalisation can still reject with `OWNERSHIP_DOMAIN_INCOMPLETE` or other existing safety errors. No ownership-store, execution, journal-write, restoration, rollback, retry, UI or production caller is added. Existing blockers and false write-ready/rollback flags remain intact.
