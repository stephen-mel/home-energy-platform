# Stage B1: linked supervised experiment records

Journal schema version 1 is the first explicitly versioned schema. Legacy JSONL records have no version or mutation linkage. They remain diagnostic evidence only, cannot validate as B1 records or support future confirmed-receipt issuance, and their existing site file continues to consume the same exclusive latch. There is no migration, recovery loader, reset or alternate execution path.

Initial records retain phase, complete review (including exact payload), exception/approval and preWriteRecheck. Added fields are journalSchemaVersion, mutationId, preparedContext and initialRecordId. preparedContext stores only the Stage A version, frozen ownership context and context fingerprint. Mutation ID is stored once at record level; all other Stage A references are reconstructed from the unchanged review for fingerprint validation, avoiding duplicate proposal/payload strings. Its fingerprint binds the exact original review and frozen preparation-time ownership snapshot, generation and checksum.

Classified records retain phase, attemptedAt/completedAt, exception, sanitised apiWrite, apiTariffReadBack, classification, later-observation placeholders and false safety flags. Added fields are journalSchemaVersion, mutationId, energySiteId, initialRecordId and classifiedRecordId. Each ID is SHA-256 of the existing canonical representation of the complete record excluding only that record's own ID. JSONL round-trip consistency is checked; non-JSON/coerced/missing required values reject. Digests are content/linkage identities, not authenticity or durable-I/O proof.

The local adapter supplies record constructors/validation through injected journalRecords ports, preserving the existing pure reconciliation dependency boundary. Its preparation port calls Stage A with the original capture, ownershipStore().read, the existing clock and randomUUID. The executor uses the resulting original review unchanged; fresh revalidation still uses prepareSupervisedExperiment and never allocates another mutation ID. Existing confirmation binding, exact payload and proposal identity are unchanged. Preparation now additionally loads and validates ownership; invalid state fails closed. The execution order remains prepare/approve/revalidate → exclusive claim → one write attempt → read-back/classification → finish.

Record constructors/validators and the journal validate context/record identity and site relationships. Claim validation runs before filesystem creation; failure produces no POST. finish validates against the detached initial record before appending; failure leaves the consumed latch intact and never retries the POST. The existing fsync behaviour and Promise<void> finish contract remain; no Stage B2 capability, receipt issuer, finaliser invocation or ownership persistence is introduced. Rejected/ambiguous/transformed outcomes remain classified evidence rather than being promoted to confirmation.

Known limitation: matching ownership outside the selected day's domain can be bound by Stage A and B1 but remains unsuitable for finalisation (OWNERSHIP_DOMAIN_INCOMPLETE). Journal linkage is not finalisation eligibility. An explicit pre-write coverage gate using the finaliser's existing rule is still required before ownership-aware execution integration. Do not rebase the snapshot or broaden selected scope to satisfy that gate. B1 changes no domain policy, TTL, approval, blocker, classification or rollback semantics. Generation-currentness, durable completion capability, receipt issuance and generation-checked persistence remain later stages.
